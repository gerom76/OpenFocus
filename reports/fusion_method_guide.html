OpenFocus · a guide to the render methods

Which fusion method should I use?

Focus stacking combines several photos, each sharp in a different place, into one that is sharp everywhere. OpenFocus offers several ways to do that. Each was given the same six tests, and this page reports how they did — in plain terms, with the pictures to back it up.

The short answer Use DTCWT.

It came first or second in most of the six tests and held colour more faithfully than anything else. If you want a non-neural option, StackMFF-V4 was the strongest of the rest. Every method beat using a single photo in every test, so any of them is better than none.

The methods, ranked

The score is how much of the achievable improvement each method captured, averaged over the six tests. 100 would mean winning every one. A plus is a test it placed first or second in; a minus is one it came last or second-last in.

DTCWT

96/100
  • +Keeping fine detail
  • +Handling a long stack
  • +Holding colour true
Works across scalesIt breaks each frame into coarse and fine layers at several orientations before combining, which is why boundaries between near and far come out cleaner than the block- and pixel-based methods manage.
Typically 107 ms on a 320×320 test image

StackMFF-V4

96/100
  • +Coping with a noisy, high-ISO shot
  • +Clean edges where near meets far
  • +Flat, low-contrast subjects
Learned, not calculatedA neural network trained on ordinary focus stacks, so it handles the common cases best. It has not been tuned for microscopy or medical imaging, where a hand-written method may be the safer choice.
Typically 34 ms on a 320×320 test image

Guided Filter

80/100
  • ·No category win
  • −Handling a long stack
Edge-aware smoothingIt builds a per-pixel map of which frame is sharpest, then smooths that map while respecting edges in the picture, which keeps its decisions from bleeding across outlines.
Typically 21 ms on a 320×320 test image

GFG-FGF

72/100
  • ·No category win
  • −Handling a long stack
  • −Clean edges where near meets far
  • −Keeping fine detail
Blends rather than picksIt decides which frame wins at each pixel, then smooths those decisions into soft weights and mixes the frames together. That hides the stepping a block-based method shows, but where two frames both claim a region the average of the two is slightly softer than either.
Typically 23 ms on a 320×320 test image

DCT

72/100
  • ·No category win
  • −Clean edges where near meets far
  • −Holding colour true
Judges sharpness in blocksIt decides which frame wins for each square block of pixels rather than each pixel, so boundaries between near and far can look slightly stepped. It also reads film grain as detail, which misleads it on noisy shots.
Typically 9 ms on a 320×320 test image

Guided Filter + IFCNN Refine

71/100
  • +Holding colour true
  • −Flat, low-contrast subjects
  • −Coping with a noisy, high-ISO shot
  • −Keeping fine detail
Can disturb a fusion that was already rightThe refinement pass converts the picture into a neural network's internal form and back again, and only the difference that round trip makes is applied - so a region it has nothing to add to is left alone. It tidies edges, but where the fusion was already correct it can still nudge things the wrong way.
Typically 37 ms on a 320×320 test image
